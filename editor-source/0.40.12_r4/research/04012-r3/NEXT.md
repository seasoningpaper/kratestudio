# 下一輪接續：先解除容量阻斷，再處理作者語法

使用本 ZIP 的最新檢查點，不能回退 r1 或 r2 覆蓋新成果。正式站維持 Sites59，已發布來源20901c7，回復 r2 可用49161bc完整來源；更舊 Sites58 仍保留。

1. **R3-B 必要驗收**：在受支援的安全瀏覽器測試副本中，實際寫入 >2.1 GB 與接近5 GB IndexedDB，重啟後逐檔讀入／校驗；測配額不足、取消、交易中斷，不碰正式使用者專案。不能用 fake-indexeddb 或 Node 磁碟結果代替。
2. **大型匯出阻斷**：現有JSZip把所有素材讀入記憶體，不具5 GB安全依據。規劃串流ZIP64／輸出目錄方案並測遊戲可執行；不要僅移除安全門檻。補齊不支援檔案儲存選擇器裝置的安全備份路徑、大型舊JSON相容匯入。目前開發版會明確拒絕上述大型路徑，不能直接發布。
3. **R3-C 真人驗收**：容量bar12px、八類圖例、深淺色及375/390/768/1366/1920px；對照保留的r2來源。原管理HTTP預覽缺少crypto.randomUUID，不能冒稱新截圖通過，也不要搜尋替代瀏覽器。
4. **R3-D 作者語法**：主解析器是src/script-import.mjs；program-files.mjs的serializeEvents目前逐事件JSON，program-sync.mjs的canonicalEventSource同時用於草稿基準與編輯器文字。先把完整IR指紋與作者顯示分開，使用現有解析器與事件模型；不可只換serializeEvents而破壞dirty/conflict判斷。program-identities.mjs目前只回填特定積木欄位，不足以保留任意未知欄位；重複內容事件的身份匹配須有來源對映或明確歧義診斷，不能靠陣列位置猜測。保留未知參數、浮動積木、草稿與原ID；無法原生表示者保留可解析相容區段。
5. **R3-E**：作者層改動後重跑50/300/500完整欄位、參照與Engine執行軌跡；不要只比較數量。現有四模式仍使用r2完整JSON作者顯示，這輪6項往返僅證明既有機制未回歸。
6. **R3-F**：拖曳殘影/取消、Logo、刪除捲動、區段垃圾桶、分隔線、積木重複/跳動、C容器/浮動積木、計數器、240FPS、角色生命週期、背景順序及缺失素材，逐項重現／回歸；本輪未全面宣稱驗完。
7. **R3-G**：必要能力通過後才同步版本為0.40.12_r3、更新文件／範例、保存完整來源、build及34資產檢查，沿用原Site/public部署。非阻斷真人聽感可待驗；資料安全與5 GB實際能力不得略過。
