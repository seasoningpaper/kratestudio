# 正式Logo人工驗收（全部待真人確認）

1. 原網址重新整理，確認左上完整圖文Logo；進「設定→介面設定」依序選淺色與深色主題，淡藍圖形保留，深色白字、淺色深藍黑字，背景無矩形。快速來回切換，檢查邊緣、閃爍及是否短暫顯示錯版。
2. 在深色主題儲存後重新整理，再以淺色主題重複；記錄網路慢速及高DPI狀況。載入期間Logo保留原位置但暫隱藏，待既有專案／主題載入後顯示。此處初始空白是防止錯版閃現，不是假定真人測試已通過。
3. 逐一確認5120×2880、3840×2160、2560×1600、2560×1440、1920×1200、1920×1080、1600×900、1366×768、1024×768、768平板、390與375手機寬；Logo不得拉長、裁切或擠壓專案名稱、工具列。測DPR2／3／4；本輪僅比例與原版規則保護檢查，尚無上述實機截圖。
4. 滑鼠點整個Logo、手機點按、鍵盤Tab聚焦後Enter／Space，應開啟原有專案首頁入口（專案清單）並聚焦目前專案。清單已開時再點不關閉、不整頁載入、不建立新專案。箭頭導覽及Escape沿用原選單。
5. 專案副本修改事件或保留未套用程式草稿，再點Logo：取消須留原編輯畫面；確認後開專案清單，事件、ID、草稿、Undo仍在。此入口不自動套用草稿或清空專案；原自動儲存照舊。模擬儲存失敗也應先詢問。
6. 瀏覽器分頁16／32圖示與iOS加入主畫面180圖示應為淡藍獨立圖形，沒有字標擠成一團或切邊。既有網站無PWA manifest，本輪不新建PWA及192／512入口。
7. 檢查原有積木／事件／流程／遊戲預覽的視覺與操作保持；檢查使用者自行指定的遊戲開場Logo未被品牌替換。

現有主題只支援明確的專案主題預設與自訂色，沒有跟隨系統選項，因此系統配色變更同步屬「不適用」，不擅自擴充。真人視覺／觸控／鍵盤瀏覽器預設行為與網站實際網路載入仍待驗，JSDOM與合成圖不等同真人通過。
