# R3-B 儲存架構與驗證範圍

原上限 2,147,483,648 bytes（2 GiB）來自 src/storage.mjs。新開發政策集中於 storage-policy.mjs：5,000,000,000 bytes，十進位 5.0 GB。IndexedDB 名稱、版本、store、專案與素材 ID 均保留。

新增措施：

- 寫入前以實際 Blob 大小統計，不信任素材的 bytes 宣告；正規化儲存中繼資料大小。
- 保留單一 IndexedDB 原子交易；估計額度不足時不開始寫入，交易失敗保留原存檔。額度估算不保證實際可寫，仍處理 QuotaExceededError。
- .koib 版本化串流專案備份：逐段讀寫 Blob、每份素材 CRC32、匯入先完整驗證再暴露資料。保留 JSON 舊格式與全部事件／模板／未知欄位。支援瀏覽器的檔案儲存選擇器時沿用原匯出按鈕；取消不修改專案。
- JSON Base64 與既有遊戲 ZIP 設 256,000,000 bytes 記憶體封裝安全門檻，超過時明確拒絕，不配置多 GB 記憶體。大型遊戲 ZIP 串流／ZIP64 尚未完成，不能宣稱 5 GB 遊戲匯出已通過。
- 單檔既有限制仍為圖片／音訊 128 MiB、影片 512 MiB，不因專案政策擴大而移除。

最終 13 項直接自動測試通過。首次測試發現素材 bytes 在載入時才新增，造成儲存前後容量不同；已改成寫入前依實際 Blob 正規化並重跑通過。保留首次失敗與修復後紀錄。

大型串流測試另有獨立可重現指令，最多 10.1 GB 暫存、180 秒；結果記於 large-backup.json。此為 Node 真實磁碟／檔案型 Blob 測試，不是瀏覽器 IndexedDB 或配額驗證。

## 發布阻斷

尚未實測瀏覽器 IndexedDB 超過舊 2.1 GB 與接近 5 GB 的儲存、重載，以及大型遊戲 ZIP。不得將政策常數、模擬 IndexedDB 或磁碟串流通過稱為實際瀏覽器 5 GB 能力已完成。依本輪發布條件，在補齊前不發布 5.0 GB 版本。

最終受控磁碟結果：素材4,990,000,000 bytes／邏輯專案4,990,001,156 bytes，匯出33,743ms、匯入31,122ms，總70,479ms、峰值RSS122,171,392 bytes，暫存清除。詳large-backup.json；不是瀏覽器驗收。
