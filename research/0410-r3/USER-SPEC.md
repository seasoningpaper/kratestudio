# Koi Maker SoftFlow 1

## 使用者歷史設計禁令總整理

### GUI / UX Negative Design Specification

**適用版本：Koi Maker 0.41.0_r2 及後續 SoftFlow 1 修訂**

本規範整理自使用者過去多次提供的設計要求、反面截圖、實際操作回饋及明確禁止事項。

這不是一般設計建議，而是必須遵守的 GUI 驗收限制。

**最高原則：不得再次把使用者已明確嚴禁的樣式，重新包裝成 Soft UI、Neumorphism、Claymorphism 或現代化設計。**



---



# 一、絕對禁止的整體設計風格

以下風格不得作為 Koi Maker 的主要視覺語言。

1. AI SaaS Dashboard。
2. Bento Grid 便當盒排版。
3. 2022-10以後常見的 AI 網站模板式構圖。
4. Dribbble 概念展示稿式排版。
5. 大量獨立懸浮卡片組成的工作區。
6. 作品集式首頁取代專業編輯器。
7. 電商商品卡片牆式布局。
8. 手機 App 展示頁式布局。
9. 過度平面化的 Material 式大色塊介面。
10. 過度擬物化的立體塑膠介面。
11. 玩具感、糖果感、橡膠感過重的視覺材質。
12. 賽博龐克、霓虹、科技發光網格。
13. 以裝飾效果凌駕操作效率的介面。
14. 只有更換顏色、圓角和陰影，沒有改善元件與布局的假重構。

Koi Maker 是日系桌面級 Galgame、視覺小說創作工具，不是 SaaS 產品儀表板。

# 二、嚴禁膠囊與不合理的圓角

使用者已反覆、明確禁止下列模式。

1. 大型膠囊按鈕。
2. 長條膠囊式導航。
3. 將全部分頁做成一排圓角凸起按鈕。
4. 巨大圓弧的面板底部。
5. 大型白色容器底部出現厚重灰藍色圓弧陰影。
6. 容器像漂浮在空中的塑膠托盤。
7. 所有工具按鈕強制使用相同的超大圓角。
8. 將文字標籤硬包進膠囊。
9. 將每個設定選項做成獨立圓角卡片。
10. 多層圓角容器互相套疊。
11. 圓角在同一組元件中忽大忽小。
12. 為製造柔軟感而把控制項不必要地增高、增胖。

尤其禁止重現 0.41.0_r2 中：

- 白色大面板下方厚重灰藍陰影。
- 巨大圓角底部。
- 塑膠托盤般的懸浮效果。
- 小按鈕全部被做成圓角浮雕。
- 文字導航被設計成膠囊。

**一般控制項允許必要的小幅圓角，但圓角必須服務元件幾何，不得成為整站裝飾主題。**

# 三、極度嚴禁不合理的框線

這是使用者極度極度強烈反對的設計問題之一。

1. 常駐細藍色外框。
2. 常駐細紫色外框。
3. 雙層描邊。
4. 三層描邊。
5. 外框加內框再加陰影。
6. 使用多層 box-shadow 偽造描邊。
7. 按鈕外面又包一層選取框。
8. 色彩選項以粗藍框包住另一層白框。
9. 滑鼠點擊後出現不合理的雙重 Focus Ring。
10. 分頁出現粗藍色或紫色弧形框線。
11. 沒有必要的細框線膠囊 例如:.palette-btn.active {

  border-color: var(--accent);

  box-shadow: 0 0 0 1px var(--accent);

}

inset 0 3px 0 var(--accent) 

12. \
    \

13. 為每個色彩選項增加重複的方形底座。
14. 輸入框同時出現邊線、內陰影及外部裝飾框。
15. 在正常 Idle 狀態就顯示強烈描邊。
16. 以大量框線區隔其實可以靠間距與文字層級區分的內容。

明確反面案例：

**0.41.0_r2 的「天空」主題色選項，出現外層粗藍框、內層白框與色塊重疊的樣式。不得再次出現。**

鍵盤焦點仍必須符合無障礙要求，但應使用單一、清楚的 Focus-visible 狀態。

不能以禁止裝飾框線為理由移除必要的鍵盤焦點提示。

# 四、嚴禁濫用陰影、光影與表面材質

1. 重度 Drop Shadow。
2. 大範圍擴散陰影。
3. 厚重底部陰影。
4. 陰影讓面板看起來離地很高。
5. 每個按鈕都有凸起陰影。
6. 每個文字欄位都有明顯凹陷。
7. 每個資源列表項目都有浮雕效果。
8. 每個圖示都有獨立陰影。
9. 發光式 Box Shadow。
10. Neon Glow。
11. 發光邊框。
12. 滑鼠移過就產生強烈光暈。
13. 重度 Glassmorphism。
14. 大面積 Backdrop Blur。
15. 玻璃反射與高光過度明顯。
16. 高亮塑膠按鈕。
17. 過度 Q 彈的 Claymorphism。
18. 在同一表面堆疊大量亮暗效果。
19. 用陰影代替真正的資訊層級。
20. 沒有統一材質規則的隨機陰影。

允許 Neumorphism，但必須是克制的柔和凸面與凹面。

**不等於每一個 HTML 元件都需要凸起或凹陷。**

# 五、嚴禁不自然的漸層與色彩

1. 螢光漸層。
2. 霓虹藍紫。
3. 高飽和糖果配色。
4. 大量 RGB 彩虹漸層。
5. 不自然的粉紫青三色混合。
6. 全頁每個區塊各自使用漸層。
7. 以大面積紫色遮蔽專業工具的內容。
8. 過度柔化至文字無法辨識。
9. 主題色與事件分類色互相混淆。
10. 每個功能都使用不同的裝飾主色。
11. 隨機生成不同顏色的背景卡片。
12. 沒有對應功能的彩色強調條。
13. 不必要的巨大紫色選取色塊。
14. 過厚的紫色選取條。
15. 全站過量使用同一種淺藍色背景，使畫面失去層次。

偏好的色彩方向仍是：

- 白色、米白、淡灰為主。
- 藍白為預設主題。
- 粉紫為第二套主題。
- 柔和天空藍、冰藍、霧紫、柔粉、薄荷綠。
- 自然、穩定、低至中低飽和度的漸層。

漸層是色彩與材質的一部分，不是整站每個容器的背景填充效果。

# 六、嚴禁沒有功能的裝飾

以下都是使用者曾明確指出的反面案例。

1. 垂直排列的彩色小圓點。
2. 裝飾性 Timeline Marker。
3. 沒有流程意義的 Stepper Dot。
4. 沒有狀態意義的 Progress Dot。
5. 隨機粉彩小圓點。
6. 沒有用途的漂浮圓球。
7. 漂浮膠囊。
8. 隨機彩色幾何圖形。
9. 沒有功能的短線。
10. 沒有功能的直線。
11. 為填補留白而加的裝飾。
12. 每個圖示強制配置一個圓角方形底座。
13. 大量重複、完全相同的圖示背景。
14. 為製造 3D 感而放置不必要的立體模型。
15. 沒有資訊用途的連接線。
16. 不必要的背景光球。
17. 過度複雜的裝飾性網格。
18. 被刻意裁切成只露出半截的白色圓角膠囊。
19. 在畫布邊緣露出半截流程節點作為裝飾。
20. 以不完整元件製造假視覺層次。

注意：

真正的流程連接線、積木連接結構、畫布網格、狀態指示器及有語意的圖示不受此禁令限制。

但每一個可見元素都必須有明確作用。

# 七、嚴禁 AI 模板式文字與排版

1. 全大寫英文裝飾標題。
2. 大字距英文眉標。
3. 類似 SaaS 行銷頁的章節小標籤。
4. 沒有必要的斜線編號。
5. 使用特殊符號代替正常資訊分組。
6. 大量使用直線、圓點、長橫線作為裝飾。
7. 不必要的 Emoji。
8. 重複的說明性廢話。
9. 每個區塊都加一段冗餘副標題。
10. 過大的標題與過小的正文混用。
11. 標題與表單控制項之間出現過量空白。
12. 用一模一樣的卡片模板安排所有文字。
13. 將純文字做成立體按鈕。
14. 將一般導航文字做成凸起控制項。
15. 將純說明文字放入陰影框。
16. 將每個標題放進大型圓角底座。
17. 無意義的裝飾色條。
18. 不適合桌面工具的超大字級。
19. 太小、低對比、不易閱讀的文字。
20. 設定文字大小後，實際介面字級沒有變化。

Koi Maker 的使用者介面以繁體中文為主。

允許必要的程式語法、英文技術名稱及正常標點，但不得製造 AI 模板式裝飾排版。

# 八、嚴禁破壞桌面編輯器布局

1. 擅自移動既有工具列位置。
2. 將四模式編輯器導航放到較低位置。
3. 無故增加大型工具列高度。
4. 將主導航改成一排浮雕按鈕。
5. 把專案資源樹做成卡片清單。
6. 用多個懸浮視窗取代連續工作區。
7. 以 Bento Grid 重新排列桌面功能。
8. 中央編輯區因裝飾而縮小。
9. 右側屬性面板無故佔用過多空間。
10. 表單欄位間距過大。
11. 設定頁的大量空白無法合理利用。
12. 同一頁的欄位左右無法對齊。
13. 內容不必要地集中在畫面中間。
14. 各頁使用互相衝突的間距系統。
15. 工具列按鈕高度不一致。
16. 文字過大導致工具列換行。
17. 文字過小導致使用者難以操作。
18. 因 Responsive Layout 而讓重要按鈕消失。
19. 不合理裁切流程節點。
20. 積木或節點無法完整捲動到可操作區域。
21. 專案資源樹的編輯、複製、刪除圖示位置不一致。
22. 將一般列表改成每筆資料都獨立漂浮的卡片。
23. 為了視覺對稱而犧牲資訊密度。
24. 將圖片編輯器工具分組拆得過於零碎。
25. 讓桌面工具看起來像手機應用程式。

桌面編輯器必須維持：

上方功能列、專案分頁、左側資源樹、中央主工作區、右側屬性面板、底部狀態列。

# 九、嚴禁不正確的互動設計

1. Idle、Hover、Active 完全沒有差異。
2. Hover 就出現突兀藍框。
3. Focus、Selected、Hover 被混成同一種樣式。
4. 點擊後產生兩層焦點框。
5. Disabled 元件看起來仍可以操作。
6. 非互動文字呈現按鈕外觀。
7. 可操作元件卻沒有滑鼠或鍵盤回饋。
8. 拖曳積木後位置跳動。
9. 拆分積木後其餘積木向上回跳。
10. 刪除事件後自動捲到清單或工作區底部。
11. 流程節點只有視覺連接，沒有真正資料語意。
12. 重複容器只是三片普通積木堆在一起，卻宣稱是完整 C 型積木。
13. 切換主題使布局或編輯資料改變。
14. 修改字級設定後畫面沒有實際更新。
15. 原生檔案選擇器與自訂介面不一致。
16. 檔案選擇區外面又套不合理的浮雕框。
17. 用新 UI 元件破壞原本的素材、遊戲預覽或編輯功能。

Soft UI 的重點是材質與回饋，而不是裝飾密度。

# 十、嚴禁不合理的程式實作方式

1. 靠大量新增 CSS 覆蓋補丁修復視覺問題。
2. 濫用 !important。
3. 同一元件同時受到多套全域樣式影響。
4. 元件樣式與設計 Tokens 不一致。
5. 重複建立不同版本的 Button、Input、Select。
6. 不檢查原有布局就大量修改 JSX 或 DOM。
7. 沒有理解元件用途便套用共用 Button 樣式。
8. 因 GUI 重構而重寫故事引擎。
9. 因換色或換主題破壞事件資料。
10. 未經測試便宣稱功能已完成。
11. 只通過單元測試就宣稱視覺驗收成功。
12. 沒有真人操作或瀏覽器驗證就直接發布。
13. 用 CSS 覆蓋造成文字大小設定失效。
14. 把同一個 Focus Ring 疊加在數個巢狀元素上。
15. 用固定寬度與大量絕對定位修補布局。
16. 使用沒有語意的元素替代必要的互動控制項。
17. 以 React 或 Vue 的名義重寫已經正常運作的整套應用程式。

React、Vue、HTML、CSS 都只是實作技術。

不得把「使用了現代框架」當成設計品質通過的證據。

# 十一、允許且真正喜歡的視覺方向

禁止上述問題，不代表使用者要求回到完全平面化的舊介面。

使用者真正希望的是：

**2019～2022 Pastel Gradient × Soft UI / Neumorphism**

輔以：

- 少量 Soft 3D。
- 克制的 Claymorphism。
- 有實際用途的微量半透明材質。
- 自然的表面明暗變化。
- 藍白與粉紫雙主題。
- 專業日本桌面創作軟體的資訊層級。

核心差異：

不是增加框線，而是改善表面質感。

不是增加陰影，而是建立合理的控制項層級。

不是增加圓角，而是讓元件幾何一致。

不是增加卡片，而是讓布局更清楚。

不是增加裝飾，而是讓操作回饋更自然。

不是到處做立體，而是讓必要的操作控制項呈現適度的按壓感。

# 十二、必須執行的驗收規則

每次修改 GUI 後，必須檢查：

1. 是否還有膠囊式導航。
2. 是否還有大圓角托盤。
3. 是否還有厚重底部陰影。
4. 是否還有常駐雙重描邊。
5. 是否還有裝飾性圓點。
6. 是否還有重複圖示底座。
7. 是否還有沒有用途的浮動卡片。
8. 是否還有文字被做成按鈕。
9. 是否還有失去資訊密度的列表。
10. 是否還有碎片化表單。
11. 是否還有工具列無故換行。
12. 是否還有重要編輯區被壓縮。
13. 是否還有失效的文字大小設定。
14. 是否還有裁切或跳動的積木與流程節點。
15. 是否還有不自然的原生檔案控制項。
16. 是否還有失去功能的原有操作。
17. 是否只修改了顏色而沒有改善材質及元件品質。
18. 是否違反使用者提供的正面、反面截圖。

凡命中上述禁止項目，均須記錄為設計缺陷。

其中影響操作、可讀性、資料安全及布局完整性的問題，應列為發布阻斷。

不得以「這是流行的 Soft UI」「這是設計師常用的風格」「自動化測試已通過」等理由忽略使用者的明確禁止事項。

# 十三、SoftFlow 1 正向設計規範與歷史作品實作指令

## 13.1 正向設計目標

本章與前面十二章的 Negative Design Specification 具有同等約束力。

過去 Koi Maker GUI 重構的主要問題，不是單純顏色不對，而是缺少整體材質設計、元件層級、色彩過渡、表面明暗及一致的互動狀態。

本次必須真正重現 **2018 年 3 月至 2022 年 8 月期間的 Pastel Gradient × Soft UI × Neumorphism 設計語言**，而不是繼續修改原有平面化介面的背景色與陰影。

最終視覺應具備：

- 2019～2022 年柔和而自然的數位介面質感。
- 白色、米白色、淡灰色構成的專業工作區。
- 冰藍、天空藍、薰衣草紫及柔粉色的自然過渡。
- 控制項表面微妙的立體厚度。
- 亮面與暗面方向一致的材質表現。
- 柔和、不突兀且具備實際用途的高光。
- 少量具有觸感的主操作元件。
- 自然、細緻且具有設計師一致性的介面。
- 適合長時間使用的日系桌面創作軟體。
- 具備成熟軟體產品的資訊密度與操作效率。

重要：**柔和立體感不等於大圓角，不等於膠囊，不等於厚重陰影，也不等於把所有元件墊高。**

本輪要提升的是整個介面的材質完成度，而不是裝飾數量。

## 13.5 Blue SoftFlow 主題

Blue SoftFlow 是正式預設主題。

視覺目標：

**清澈、柔和、安靜、有少量立體材質的日系桌面創作工具。**

色彩以以下方向為主：

- 白色：主要編輯內容。
- 淡米白：局部溫暖表面。
- 淺灰藍：工作區環境。
- 冰藍：次要表面。
- 天空藍：主要操作。
- 少量薰衣草紫：溫和的色彩過渡。
- 深灰藍：正文與標題。

主要背景應保持低飽和度。

重要操作可以使用天空藍向冰藍過渡的自然漸層，但不能讓整個編輯工作區成為藍色漸層背景。

白色不是沒有設計的純白色塊，而是與鄰近表面具有細膩明度、色溫及材質關係的白色。

避免整站所有面板使用同一種淡藍底色。

## 13.6 Lavender SoftFlow 主題

Lavender SoftFlow 為第二套可切換主題。

視覺目標：

**柔和、優雅、略帶暖意，具有 2020～2022 年粉紫 Soft UI 特徵。**

使用：

- 米白。
- 柔和白。
- 淺灰紫。
- 薰衣草紫。
- 櫻花粉。
- 少量淡藍。

主題切換後只改變色彩與合理的材質參數。

不得改變：

- 導覽位置。
- 分頁幾何。
- 工作區大小。
- 編輯器資料。
- 按鈕尺寸。
- 清單資訊密度。
- 使用者目前選取的項目。

粉紫主題不能變成粉紅色手機 App，也不能將所有表面全部染成紫色。

## 13.7 真正的 Soft UI 材質設計

建立以下五種明確的表面：

### Base Surface

供編輯器背景、資源樹、清單、程式碼區、流程畫布使用。

特徵：

- 柔和但穩定。
- 以背景明度和色溫產生層次。
- 主要保持連續平面。
- 適合大量資訊。

### Raised Surface

僅用於真正可按壓的操作控制項。

特徵：

- 微妙的凸面厚度。
- 左上亮部、右下暗部。
- 小範圍柔和陰影。
- Hover 時略微改變亮度。
- Active 時降低高度或產生微凹回饋。

### Recessed Surface

用於真正可輸入的表面。

特徵：

- 輕微內凹。
- 清楚的輸入邊界。
- 表面比附近背景略有明度差。
- 不依賴強烈陰影辨識。

### Primary Surface

僅用於主要行動。

特徵：

- 低至中低飽和度藍色或紫色漸層。
- 比一般控制項稍明顯的材質。
- 清楚的 Hover、Pressed 與 Disabled。
- 不使用常駐裝飾外框。

### Popup Surface

供選單、對話視窗及必要的浮動編輯器使用。

特徵：

- 輕微高於背景。
- 柔和且克制的邊緣明暗。
- 清楚的層級及可讀文字。
- 適量而非誇張的空間深度。

所有表面透過一套 Design Tokens 管理。

本次不能再次使用多組互相衝突的 CSS 來臨時覆蓋。

## 13.8 元件正向設計規則

### 主導航與四模式分頁

採用專業桌面軟體常見的連續式 Tabs。

- 正常狀態使用文字和適度留白。
- Hover 以淡淡的背景明度變化回饋。
- Active 使用清楚但克制的底線。
- 不增加按鈕高度。
- 不額外占用中央工作區。
- 恢復使用者指定的既有導覽位置。

### 一般按鈕

- 保持緊湊且合理的控制項尺寸。
- 使用微量表面起伏。
- 具有自然的按下回饋。
- 統一小幅圓角。
- 不將按鈕外形變成整站視覺主題。

### 主要操作按鈕

例如儲存、開始預覽、建立專案。

- 使用 Blue 或 Lavender 主色。
- 允許少量自然漸層。
- 有清楚但不刺眼的 Hover。
- 有可辨識的 Pressed。
- 使用一致的柔和材質。
- 不添加額外描邊裝飾。

### 輸入欄位

- 淡色微凹表面。
- 清楚且可閱讀的文字。
- 標籤與欄位距離一致。
- 使用合理的表單網格對齊。
- 鍵盤焦點只有一套清楚的提示。

### 專案資源樹

- 保留真正的樹狀資訊結構。
- 採用連續式清單。
- 對齊圖示、縮排與文字。
- Active 使用淡色選取表面和文字變化。
- 操作圖示的位置一致。
- 保持桌面創作工具的緊湊感。

### 事件編輯器

- 優先顯示事件內容。
- 事件分類色維持既有語意。
- 使用連續事件列表。
- 避免不必要的卡片分隔。
- 選取事件時，整列具有自然的明度變化。
- 行操作按鈕保持小巧、明確、不干擾閱讀。

### 設定頁與屬性面板

- 使用一致的欄位網格。
- 標籤、輸入框與說明文字有明確層級。
- 相同類型欄位共享寬度及間距。
- 分組使用標題、適度空白及必要的分隔。
- 不把每個選項拆成獨立浮動卡片。
- 調整字級後必須立即反映至相關 GUI。

### 圖片編輯器

- 中央畫布維持最大可操作空間。
- 相關工具集中排列。
- 操作工具採一致尺寸。
- 不讓工具列因新增材質而變厚。
- 圖片預覽、圖層及屬性面板保持專業軟體配置。

### 流程與積木編輯器

- 保留既有事件模型及連接語意。
- 積木幾何優先服從連接機制。
- 流程節點的視覺樣式應反映事件類型。
- 必須可以正常平移、縮放和選取。
- 不將單純的視覺連接當成真正可執行的連接。

## 13.9 字體與文字大小

字體是正式設計系統的重要部分，不能再次被忽略。

要求：

- 繁體中文閱讀清楚。
- 標題、正文、輔助資訊建立一致比例。
- 以字重、字級與間距建立層級。
- 不依賴外框區分每段文字。
- 不為了縮小版面而讓文字難以辨識。
- 不為了柔和風格而降低文字對比。

必須檢查：

- 超小。
- 小。
- 預設。
- 大。
- 特大。

這五種文字大小設定都需真正影響對應 GUI。

使用一致的字級變數或 Typography Tokens。

不得因固定像素值、CSS 特異性或局部覆蓋規則，導致文字大小功能再次失效。

字體調整後應重新計算必要的布局空間，避免截字、控制項重疊或錯誤換行。

## 13.10 建立真正的視覺設計差異

此次不能只以 CSS Token 改動數量作為完成標準。

每一個主要畫面都應回答：

1. 原版的視覺問題是什麼？
2. 參考的歷史設計作品是哪一件？
3. 該作品真正使用了什麼材質或互動方式？
4. 如何轉換成 Koi Maker 的專業工作區？
5. 哪些視覺細節被刻意省略？
6. 是否改善資訊層級？
7. 是否保留原本的操作效率？
8. 是否違反前十二章禁止事項？

重構成果必須可以從實際畫面辨識。

應能明顯看到：

- 表面不再單調平面化。
- 控制項不再只是同一種底色。
- 主次操作有自然區別。
- 輸入與按壓表面有合理差異。
- 工作區的白色與淺灰色具有細節。
- 局部漸層具有自然的色彩過渡。
- 視覺層級更加完整。
- 不需要額外裝飾就能呈現設計品質。

## 13.11 先建立視覺驗收基準，再推廣至全站

請從目前正式 Koi Maker 的原始程式碼及實際畫面開始。

在不破壞資料及既有功能的前提下，優先選擇以下五種代表性頁面作為 Design System 驗證：

1. 事件編輯器。
2. 專案資源樹。
3. 介面設定。
4. 素材庫與檔案匯入。
5. 圖片編輯器。

每個代表性頁面都要產生可比較的改版前後截圖。

先確認：

- 材質符合目標。
- 導覽與按鈕形狀正確。
- 沒有厚重底部陰影。
- 沒有雙層外框。
- 沒有大量膠囊。
- 表單沒有碎片化。
- 資源列表維持資訊密度。
- 文字大小設定可以使用。
- 原有功能仍正常。

完成這些代表性頁面的視覺與功能驗證後，再將相同設計系統逐步擴展至其他畫面。

這是為了防止錯誤的共用元件被一次套用到整個網站。

## 13.12 實作工程與版本安全

本次只修改既有 Koi Maker 正式專案。
