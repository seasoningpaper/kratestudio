# Koi Maker 0.41.0_r4 最終瀏覽器驗收

日期：2026-10-24（台灣）。來源：`77d8d7c49bc936251b7fadd4561e94e6ddbeea43` 候選版；正式發布結果另記於 `DEPLOYMENT.json`。原正式站為 Sites 64／`f2db20232f5349b2907c3836fdcf549e8c9b81ae`，保留原版本可回復。測試使用隔離儲存名稱的完整應用程式副本，沒有清除或寫入正式站使用者專案。

## 瀏覽器與版面

在 Chrome 的完整應用程式 iframe 實際執行五個 CSS viewport：2560×1600、1920×1080、1600×900、1366×768、1024×768。讀檔畫面各尺寸整頁水平溢出為 0；頂部均保持歷史 0.40.12 的兩列資訊架構、四模式於右上、工具於右下、文件分頁於頂部下方。讀檔屬性欄在前四種寬度為 280px，1024px 時移至畫布下方並局部捲動；標籤沒有垂直堆字。截圖：`final-qa/load-screen-1366.jpg`，歷史頂部和七張缺陷比對沿用 `comparisons/` 的原始證據。

Chrome 本機縮放快捷鍵在可用的雲端瀏覽器中沒有改變 `devicePixelRatio` 或 `innerWidth`；瀏覽器內部縮放設定頁亦受環境政策禁止，因此**90%、125%、150% 原生 Chrome 縮放沒有宣稱實測成功**。以實際 Chrome iframe CSS viewport 補測對應可用尺寸：1920/90%=2133×1200、1600/125%=1280×720、1366/150%=911×512、1024/150%=683×512，另有 100% 五尺寸及上一輪五級文字×五寬度的 25 組實測。這驗證響應式 CSS 的視窗大小，不能驗證 Chrome 原生縮放的字形光柵化、系統縮放或瀏覽器彈窗行為。

911×512 的讀檔編輯器曾在上下排列後把屬性區壓至 29px，屬阻斷操作的缺陷。僅在 viewport 高度≤620px 且編輯器容器寬≤720px 時，將畫布和屬性各設 190px 最小列高，使編輯區自身捲動。重建後實際 Chrome 量測為 190px 屬性區、總 380px 捲動內容位於 198px 工作區；可捲至屬性欄操作下拉選單。沒有變更頂部布局、故事畫布縮放或資料模型。截圖：`final-qa/short-viewport-fixed.jpg`。683×512 的行動窄版隱藏左欄，頂部仍有四模式和工具，讀檔表單可操作。

## 建置與限制

最終版本的 `npm run build` 通過，Worker 僅 39 個應用資產、ESM fetch 有效；`npm test` 119/119，`npm run test:softflow` 16/16（其中 13 重疊主回歸，去重 122），`npm run check:assets` 39/39 逐 byte 一致、根路徑 200、版號 r4。正式建置預覽實際開啟，標題、頂部與側欄顯示 r4，見 `final-qa/r4-release-preview.jpg`。唯一觀測到的 Console error 文字為瀏覽器擴充元件傳送 metadata 失敗，未見應用程式錯誤。

已知限制：雲端瀏覽器不支援本輪原生 Chrome 縮放驗收。683×512 的底部「事件屬性」行動抽屜在模板編輯分頁會顯示遮罩而無故事屬性面板；讀檔編輯器自身表單仍可在關閉遮罩後直接操作。這是窄行動視圖的導覽不一致，非資料損壞或桌面讀檔編輯阻斷；保留後續修正，不在發布階段改動已驗收的頂部與模板結構。原生色彩系統視窗的取消操作未於此雲端環境完成真人驗收；共用 ColorField 的即時、取消、還原與資料保存由既有測試覆蓋。沒有宣稱已完成實機觸控、系統字體縮放或全量視覺像素比對。
